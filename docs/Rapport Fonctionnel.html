1 Vision & Problème Résolu

Le Problème

Un auditeur d'accessibilité numérique doit vérifier qu'un site web respecte le RGAA (Référentiel Général d'Amélioration de l'Accessibilité), un cadre légal de 106 critères répartis sur 13 thématiques. Ce travail est :

  • 🔁 Répétitif : les mêmes erreurs reviennent d'un audit à l'autre.
  • 🧠 Cognitif : retrouver la bonne recommandation parmi 106 critères est lent.
  • 📂 Silotté : chaque rapport vit dans un fichier Word isolé, sans capitalisation.

La Solution

Une application web full-stack qui :

1
Extraction automatique

Lit les rapports Word .docx et en extrait tous les constats d'accessibilité structurés.

2
Capitalisation

Stocke les constats dans une bibliothèque dédupliquée — chaque erreur unique n'apparaît qu'une seule fois, avec un compteur d'occurrences.

3
Augmentation IA

Offre un assistant conversationnel (RAG) qui répond aux questions de l'auditeur en s'appuyant sur les audits passés et le référentiel officiel.

2 Architecture Globale

Le projet est un monorepo (un seul dépôt pour le frontend et le backend), connectés via tRPC, un protocole qui partage automatiquement les types TypeScript des deux côtés.

3.1 Le Parseur Word

C'est le cerveau de l'extraction. Un fichier Word n'est pas une base de données : c'est du texte libre. Le parseur doit inférer la structure à partir de conventions textuelles.

3.2 Le Moteur de Dédoublonnage

Si 10 audits signalent la même erreur, on ne veut pas 10 entrées. Le moteur garantit une seule entrée avec un compteur occurrenceCount.

1
Normalisation sévère

Lowercase, suppression des accents, suppression de la ponctuation. "L'image du Lôgo !" → "limage du logo "

2
Hash SHA-256

Calcule une empreinte de 64 caractères sur le texte normalisé + l'ID du critère → signatureHash.

3
Upsert en base

Si le hash n'existe pas → création d'un nouveau template. S'il existe → incrémentation de occurrenceCount.

⚡ ImportantCe mécanisme crée la bibliothèque de templates (finding_templates) — la "mémoire" du système, indépendante des rapports individuels.

3.4 Le Knowledge Hub — Intelligence Artificielle

💡 Pour un juniorImaginez que vous interrogez ChatGPT, mais avant de vous répondre, il fouille d'abord dans VOS documents internes pour enrichir sa réponse. C'est le RAG (Retrieval-Augmented Generation).

Sub-module A — Service d'Embedding

Transforme du texte en vecteurs (suite de nombres) qui capturent le sens du texte. Deux phrases similaires ont des vecteurs proches → ChromaDB peut les trouver par similarité.

"L'image n'a pas d'attribut alt"  →  [0.12, -0.87, 0.43, ...]
"Texte alternatif manquant"       →  [0.11, -0.85, 0.41, ...]  ← similaire !

Sub-module B — Pipeline d'Ingestion

FonctionDéclencheurDescription
indexReportFindings()Automatique après importIndexe les constats en arrière-plan
bootstrapFromExistingFindings()Migration one-shot manuelleMigration des données v1
indexValidatedFinding()Via outil MCPAjout manuel d'un expert
⚡ CritiqueL'indexation ChromaDB est toujours en fire-and-forget (setImmediate). Si ChromaDB est en panne, l'import MySQL continue sans erreur. Le métier n'est jamais bloqué par l'IA.

Sub-module C — Moteur RAG (ragEngine.ts)

3 fonctions publiques principales :

FonctionUsageCollections interrogées
askAccessibility(question)Question librergaa_referential, rgaa_findings, rgaa_code
analyzeCode(html)Analyse HTMLrgaa_referential, rgaa_code, rgaa_findings
suggestFix(problem, ref)Correctionrgaa_code, rgaa_findings

Formule de scoring :

score = (1 - distance_cosine) × poids_collection
      + boost_occurrences (log)
      + boost_confidence (niveau de validation)

4 Couche API — tRPC

tRPC partage automatiquement les types TypeScript entre le frontend et le backend. Si un paramètre change côté serveur, TypeScript signale l'erreur côté client immédiatement.

💡 NoteToutes les procédures protectedProcedure requièrent un utilisateur authentifié. publicProcedure sont accessibles sans connexion (ex: hub.ask).

9 Glossaire pour les Juniors

RGAA
Le "code de la route" de l'accessibilité web en France. 106 règles à respecter.
Constat
Une erreur d'accessibilité trouvée lors d'un audit.
Template de Constat
Version "générique" d'un constat, réutilisable entre plusieurs audits.
tRPC
Un tunnel direct entre le code serveur et le code client, avec vérification des types.
ORM (Drizzle)
Outil qui transforme des lignes de base de données en objets JavaScript.
ChromaDB
Base de données qui recherche par sens plutôt que par mot exact.
Embedding
La "traduction" d'un texte en une suite de nombres qui capture son sens.
RAG
Technique où l'IA consulte vos données privées avant de répondre.
SHA-256
Fonction qui génère un code unique (empreinte) à partir de n'importe quel texte.
MCP
Standard permettant à une IA externe (Claude…) d'utiliser vos outils.
Fire-and-Forget
Lancer une tâche en arrière-plan sans attendre qu'elle se termine.
Monorepo
Un seul dossier de projet contenant à la fois le frontend et le backend.
Upsert
Insérer si ça n'existe pas, mettre à jour si ça existe déjà.
JWT
Jeton de sécurité signé qui prouve qu'un utilisateur est connecté.
SPA
Single Page Application : une seule page HTML dont le contenu change dynamiquement.

10 Roadmap Future

🔵 Phase 1 — RAG Multi-Agents
  • RAG Référentiel : Vérité immuable du RGAA et WCAG.
  • RAG Expertise : Bibliothèque de constats capitalisés.
  • RAG Pédagogique : Explications simplifiées et exemples conformes.
  • RAG Patterns : Détection de patterns non-accessibles fréquents.
🟣 Phase 2 — Anti-Hallucination
  • Seuils de similarité stricts (>85%) : L'IA ne répond que si le contexte est pertinent.
  • Citations obligatoires : Chaque affirmation liée à une source précise.
  • Prompt Guards : L'IA admet explicitement quand elle ne sait pas.
🟠 Phase 3 — Intégrations Avancées
  • Computer Vision : Analyser des captures d'écran pour détecter des erreurs visuelles.
  • Knowledge Graph : Liens logiques entre critères et composants.
  • Connecteur MCP Global : Interface unique pour Claude, ChatGPT… dans l'IDE.
